# AI 原生创业方案引导

## 概述

用分批问卷引导用户，按「创意 → MVP → 上线 → 规模化」四阶段框架，产出一份完整的创业方案。框架来自《创始人实战手册：打造 AI 原生初创企业》（Claude 出品）。

核心原则是**证据先于开发**：每个阶段都有一道退出门槛，要用证据跨过。门槛没过时，标出风险继续往下写，不阻断用户。

## 参考文件

| 文件 | 什么时候读 |
| --- | --- |
| `references/questionnaires.md` | 开场前读，按批次发问卷 |
| `references/methodology.md` | 每批回答后，查对应阶段的门槛和陷阱；生成方案前完整读一遍 |
| `references/prompts.md` | 生成方案时，挑出相关模板，填入项目信息 |
| `references/plan-template.md` | 生成方案时，严格按这个结构输出 |

## 流程

1. **开场**：用两三句话说明安排：共 5 批问卷，每批几分钟，最后生成四阶段方案；任何问题都可以答"不知道"或"跳过"。然后发出第 0 批。
2. **发问卷**：一次性发出本批全部问题，编号列出。发之前删掉所有 `〔AI：…〕`，普通括号保留。
3. **第 0 批回答后**：回复两段，然后发第 1 批。
   - **本批小结**：3–5 行。
   - **初步阶段判断**：按进展判断当前大概处于哪个阶段，一句话说依据。
4. **第 1–4 批回答后**：回复固定四段，然后直接发下一批，不多轮追问。
   - **本批小结**：3–5 行，复述关键信息。
   - **门槛判定**：按下面的「判定规则」给本阶段门槛标 ✅ / ⚠️ / ❌，一句话说依据。
   - **反方提示**：1–3 条针对本项目具体假设的反驳。优先结合 `methodology.md` 中该阶段的陷阱；项目特有的风险（行业合规、利益冲突、平台规则等）也可以写。
   - **可选补充**：列出最关键的 1–3 个空白，用户可以补，也可以不补。
   - 第 4 批没有下一批。四段之后加一句："需要补充的话直接回复；不补就回复'生成'。"收到回复后进入第 6 步。
5. **用户提前结束**（说"直接生成""后面跳过"等）：
   - 本批已答的内容直接并入方案，不再单独回复四段。
   - 本批未答的题和后续批次全部标【待补】，立即进入第 6 步。
6. **生成方案**：完整读 `methodology.md`，再读 `prompts.md` 和 `plan-template.md`，按模板输出完整方案。
   - 环境能写文件时，保存为 `<项目名>_AI原生创业方案.md`。没有项目名就取一句话描述里的关键词，如 `口腔诊所回访_AI原生创业方案.md`。告诉用户保存路径。
   - 不能写文件时，在对话中完整输出。
7. **收尾**：用一段话告诉用户当前所处阶段、最大风险，以及本周第一件该做的事。

## 判定规则

**单项判定**

- ✅：有证据。证据只包括访谈记录、数据、真实用户行为。
- ⚠️：有部分证据但不够，或只有用户自述 / 设想。
- ❌：没有证据，或这一步还没开始，或用户跳过了。

**多项合成**：一个门槛有多个子项时，全部 ✅ 才算 ✅；全部 ❌ 算 ❌；其他情况都算 ⚠️。下表的常见情况**优先于**合成规则，匹配上就按表判。

| 常见情况 | 判定 |
| --- | --- |
| 只有原型，没有用户访谈或真实用户行为 | 创意门槛 ⚠️（原型不算验证，交流才是证据） |
| 有真实用户行为（使用、付费），但没做过访谈 | 创意门槛 ⚠️（有行为证据，但问题本身没问清楚） |
| 还没有产品或用户 | MVP 门槛 ❌（尚未进入） |
| 有增长但没设基准，增长来自朋友、投资人网络或一次曝光 | MVP 门槛 ⚠️，注明"可能是虚假 PMF" |
| 有留存、付费或推荐，并在多个迭代周期持续成立 | MVP 门槛 ✅ |
| 增长靠创始人亲自推动，没有可预测的渠道和单位经济 | 上线门槛 ⚠️ |
| 答不出"巨头复制你，用户为何留下"，或只给出空泛理由（"体验更好""我们更懂用户"），或跳过了第 4 批 | 规模化门槛 ❌ |

门槛未过时，在方案中该阶段开头加 ⚠️ 风险提示，后续阶段照常写，并注明前置条件。不拒绝，不中断。

## 写法规则

**工具**：方案中每一步都要标出能力类型：对话研究、工作流自动化或智能体编程。
- 用户用的工具里有 Claude（包括同时用其他工具），按 Claude 写：对话研究写 Chat，工作流自动化写 Cowork，智能体编程写 Claude Code。
- 用户只用 WorkBuddy、Codex 等其他工具时：
  - 「推荐工具」列只写能力类型。
  - 在方案概览后加一段「工具说明」，解释三类能力各指什么，并提醒用户：在自己的工具里找对应功能，找不到就手动完成。
  - 不要断言某个工具具备或不具备某项能力。
- 上下文文件（T12、T19 中的 `CLAUDE.md`）：Claude 用户写 `CLAUDE.md`，Codex 用户写 `AGENTS.md`，其他工具写"项目上下文文件（文件名以工具文档为准）"。

**渠道**：邀约、跟进类的提示词（如 T8），按第 0 批第 7 题回答的联系渠道改写，不要默认用邮箱。

**方案用途**（第 0 批第 5 题）：
- 自己执行：重点写行动计划、提示词和「本周三件事」。
- 内部汇报：重点写门槛状态总表、风险和资源需求。
- 对外融资：重点写问题假设、市场、护城河叙事。风险写成"已识别的风险 + 应对计划"，但不隐藏 ⚠️ / ❌。

## 常见错误

| 错误 | 正确做法 |
| --- | --- |
| 一题一题追问，问很多轮 | 每批一次发完；空白只放进「可选补充」 |
| 编造市场规模、竞品数据或用户数据 | 写【待补】并给出验证方法；推断内容加「💡 AI 推断，待验证」 |
| 把用户的判断当成证据 | 用户自述最多算 ⚠️；只有访谈、数据和用户行为算证据 |
| 每个阶段把所有模板都放进方案 | 每阶段放最关键的 3–5 个完整提示词，其余只列编号 |
| 只附空白提示词 | 把【】替换成项目信息，缺的信息标【待补】 |
| 门槛没过就不往下写 | 标 ⚠️ 风险后，四个阶段都写完 |
| 反方提示泛泛而谈（"市场竞争激烈"） | 针对项目的具体假设，写出具体的反驳 |
