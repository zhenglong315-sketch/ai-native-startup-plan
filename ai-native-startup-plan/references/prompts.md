# 提示词模板库 T1–T28

> 由原书各阶段"练习"改写。写进方案时，把【】替换为项目的真实信息；信息缺失时保留【待补：……】。
> 「📍 发到」中的 Chat / Cowork / Claude Code 分别对应对话研究 / 工作流自动化 / 智能体编程三类能力；用户使用 WorkBuddy、Codex 等其他工具时，按能力类型换成对应功能。

> 用法：复制后替换【】中的内容。提示词由原文"练习"改写。每个模板下的「📍 发到」标明在哪个工具里用，箭头表示按顺序在几个工具间接力。

**发到哪个工具：分工规律**

| 工具 | 适合 | 识别关键词 |
| --- | --- | --- |
| **Chat** | 动脑的事：打磨假设、当反方、审访谈题、诊断、设计流程；不需要接入文件或系统 | 其余情况都用它 |
| **Cowork** | 耗时的事务和汇总：处理大量资料、建名单、发邀约、排日程、每周汇总、定时任务；需要连接文件夹、邮箱、日历等 | 汇总、名单、邀约、排期、每周、定时 |
| **Claude Code** | 碰代码的事：写原型、开发、审查代码库、安全扫描、写测试 | 代码库、原型、审查代码、测试用例 |

### 创意阶段

**T1 可检验问题假设**

> 📍 发到：Chat

```
句式：【谁（具体角色 + 组织类型）】每【频率】要花【多少时间 / 代价】在【具体环节】上，
因为【现有方案的具体缺陷】。

反例："大家做费用报销很费劲"（只是观察）
正例："中型企业的财务经理每周要花四个多小时核对报销提交材料，因为现有工具无法与财务核算软件集成"

提示词：
这是我的问题陈述：【陈述】。请逼我把它说具体：它是否准确回答了谁遇到这个问题、
频率多高、影响多大、目前如何应对？逐项指出模糊之处，帮我改写成一个可以检验的假设。
```

**T2 反证压力测试**

> 📍 发到：Chat

```
请站在反方，尽全力推翻下面这个假设：【假设】。
请寻找：1）负面市场信号；2）做过类似事情但失败的竞争对手及失败原因；
3）与假设相矛盾的客户行为模式；4）结构性障碍。
不要给支持性综述，只给最有力的反驳。
```

**T3 分层竞争格局**

> 📍 发到：Chat

```
请分层梳理【领域】的竞争格局：直接竞争对手、间接竞争对手、潜在收购方、可能进入本领域的相邻玩家。
对每一类，给出最有说服力的论证：为什么他们会成功而我（【我的方案】）不会？
他们的方法为什么可能更好？客户为什么会选他们？我的差异化为什么未必像我以为的那样牢固？
要给出真实的威胁，不要只给最容易驳倒的版本。
```

**T4 竞品评价汇总**

> 📍 发到：**Cowork**（需要抓取、汇总大量评价）

```
请汇总【竞品列表】在【评价来源】上的公开用户评价，提炼现有方案尚未解决的主要抱怨，
按出现频率排序并附代表性原话。然后对照我的假设【假设】：它回应了其中哪几项？哪些完全没回应？
```

**T5 市场规模与结构**

> 📍 发到：Cowork → Chat（先用 Cowork 从行业报告中提取数字，再到 Chat 建模、检验假设）

```
请用公开数据为【市场】建立 TAM / SAM / SOM 模型，列出每一层的计算假设，并逐条检验这些假设。
另外判断：1）市场处于扩张、整合还是成熟期，这对进入时机和差异化意味着什么？
2）采购决策关系：谁掌握预算？谁影响决策？两者是不是同一个人？
```

**T6 外部趋势**

> 📍 发到：Chat

```
请找出未来两年可能显著影响【市场】的三个外部趋势（监管 / 技术 / 人口结构），
逐个判断它对我的具体假设【假设】是利好还是阻力，并说明理由。
另外，请找出解决过类似问题的可类比市场，总结哪些做法有效、哪些无效。
```

**T7 访谈问题审查**

> 📍 发到：Chat

```
下面是我自己写的访谈问题：【问题列表】。目标受访者：【角色，如有多种角色请分别列出】。
请标出所有：1）诱导性问题；2）面向未来的问题（"你会不会用……"）；3）过于宽泛的问题；
4）容易引出"社会期待的答案"而不是诚实回答的问题。
把它们改写成询问过去具体经历的问题（"讲讲你上次遇到这个问题时的情况"）。
再为访谈中最容易被回避的两三个环节设计追问。
```

**T8 邀约与访谈自动化（交给工作流自动化工具）**

> 📍 发到：**Cowork**（通过 MCP 连接邮箱和日历）

```
目标画像：【岗位 / 公司类型 / 职级】
任务：1）研究并整理结构化的潜在客户名单，附核实过的联系方式；
2）根据每个人的角色和背景起草个性化邀约邮件；
3）通过邮箱和日历连接处理回复、约时间，把访谈排进日历；
4）第 7 天给未回复的人起草跟进邮件；
5）维护跟踪表，字段：姓名 | 角色 | 公司 | 联系状态 | 跟进节奏 | 访谈完成情况。
```

**T9 访谈分析**

> 📍 发到：Chat + Cowork（单次复盘用 Chat；每 5 次汇总交给 Cowork；「不对称」追问回到 Chat）

```
【单次复盘】这是本次访谈的笔记：【笔记】。我的假设是：【假设】。
请分出三类：支持假设的内容 / 挑战假设的内容 / 真正出乎意料的内容。

【每 5 次汇总】汇总这 5 份访谈笔记，列出两份清单：支持假设的证据、挑战假设的证据，
并提炼反复出现的主题和矛盾。
（如果支持清单明显更长）请追问：这种不对称来自真实数据，还是来自我原本就想找到的答案？
```

**T10 方案关键假设**

> 📍 发到：Chat

```
这是我的解决方案构想：【构想】。
请指出这个设计最依赖的三个假设。对每个假设回答：要成立需要满足什么条件？
如果不成立，会造成什么后果？
另外请检查：这个设计回应的是验证过程揭示的实际问题，还是我最初想当然的问题？
```

**T11 单一核心交互原型**

> 📍 发到：**Claude Code**

```
核心交互：【方案赖以成立的那一个交互】
给编程智能体的指令：只实现这一个交互，用能呈现给真实用户并获得反应的最小功能范围，不做其他功能。

试用记录表（5 人，均符合已验证的目标画像）：
| 试用者 | 角色 | 完成核心交互了吗 | 原话反应 | 意外发现 |
结论：□ 继续开发  □ 回到起点重新思考
```
